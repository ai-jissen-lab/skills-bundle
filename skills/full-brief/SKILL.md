# full-brief（フルブリーフ）

別のAIや外注先に仕事を頼むとき、指示文を短く書きすぎると、返ってくるのは平均的な成果物になる。悪くはない。ただ、自分の事業の実態は入っていないし、好みも反映されていない。宣伝調で、いかにもAIが書いた感じがする。結局、直すのに自分で作るのと同じくらい時間がかかる。

書き直しを重ねると評価ははっきりする。背景を省いた短いプロンプトは低品質だ。問題は受け手の能力ではなく、渡した情報の量と質である。

このスキルは、外部に渡す指示文を「文脈ゼロの相手が、これだけで作れるか」で設計するためのルール。肝は3つ。

1. **受け手は文脈ゼロ、が前提**。渡した指示文に書いてあることしか知らない。知らない部分は一般論で埋められる
2. **含める要素は6つに固定する**。事業の実態／背景と目的／成果物の仕様／制作基準・好み・嫌うもの／禁止事項／受け手の自己チェック項目
3. **冒頭に前提の一文を付ける**。「書いていないことは、一般論で埋めず、不足として指摘してください」

ひな形は `templates/full-brief.template.md`。

## 使う場面

- 別のAI（普段使いとは別のモデルやサービス）や外注先に、文章・原稿・制作物を頼むとき
- 短いプロンプトで頼んだ成果物の質が安定しないとき
- 同じ種類の依頼を繰り返し外部に出すとき（基準部分を使い回す）

普段使っているAIアシスタントは違う。メモリがあり、過去のやり取りがあり、好みも蓄積されているから、短い指示でも文脈で補ってくれる。このスキルは「文脈のない相手」専用だ。

## フルブリーフの6要素

1. **事業の実態**：普段やっていること。実数・実績を含める。規模感が分からないと、文章の温度も提案の粒度も合わない。実数は確認できるものだけを書く
2. **背景と目的**：なぜこれを始めるのか、何のために作るのか。目的が分かれば、仕様に書いていない判断を、受け手が目的側に倒して決められる。成功の判定まで書くと、受け手の自己チェックの基準にもなる
3. **成果物の仕様**：何を、どんな形で、いくつ作るか。形式・分量・納品の形。形式と分量は数字で書く。「長めに」「いくつか」では受け手ごとに解釈が割れる
4. **制作基準・好み・嫌うもの**：普段の制作基準と、嫌うもの。いちばん省略されやすく、いちばん効く要素。「嫌うもの」を書かないと、受け手は無難な宣伝調に寄せる。AI感、業者感、宣伝調のような「出してほしくない感じ」は、嫌うものとして明示する。具体例を1つ添えるとなお良い
5. **禁止事項**：やってはいけないこと。作ってはいけない数字、触れてはいけない情報、使ってはいけない表現。「作ってはいけない数字」は特に明示する。受け手は実績らしい数字を置くと文章が締まることを知っているので、禁止しなければ推測の数字が入り込む
6. **受け手の自己チェック項目**：納品前に受け手自身が確認する項目。基準を渡すだけでは、受け手は照合しない。チェック項目の形にして「納品前に実施すること」と明示する

## 冒頭の前提一文

フルブリーフの冒頭には、この一文を付ける。

> あなたは私の事業の文脈を持っていません。この指示文に書いてあることだけを前提に作ってください。書いていないことは、一般論で埋めず、不足として指摘してください。

この一文があると、受け手は「分からない部分をそれらしく埋める」動きをやめて、不足を不足として返してくる。それだけで、出来上がりの質と、やり直しの回数が変わる。

## なぜ効くのか

効く理由は、判断の材料が揃うからだ。

実態と背景があれば、受け手は「この事業ならこうだろう」と具体で書ける。基準と嫌うものがあれば、一般的な「良い文章」に均さずに済む。禁止事項があれば、地雷を先に避けられる。自己チェック項目があれば、受け手は出す前に自分で照合して、基準から外れた部分を直してから納品する。

自己チェックの最後の項目（指示文に書いていない前提で進めた箇所の明示）があると、受け手側の推測が可視化されて、こちら側の確認がピンポイントになる。

短いプロンプトで起きる問題の多くは、受け手の腕ではなく、こちらの渡し方の問題だ。背景を省くのは書き手の都合でしかなく、その省略分は必ず品質側に跳ね返る。

## 使い回し方

6要素のうち、案件ごとに書き直すのは②背景と目的の一部と③仕様だけである。①事業の実態、④制作基準・好み・嫌うもの、⑤禁止事項は事業側の固定情報なので、テンプレートとして保存しておき、案件のたびに貼って差し替える。初回の作成に時間はかかるが、2回目以降は短いプロンプトを書くのと大差ない手間で、出来上がりの質が安定する。

## やらないこと

- 文脈のある普段使いのアシスタントへの指示にまで、毎回フルブリーフを持ち込む（このスキルは文脈ゼロの相手専用）
- 実態に、確認できない実数や誇張した数字を書く
- 「嫌うもの」を書かずに、受け手のデフォルト（平均的な宣伝文）に任せる
- 禁止事項を省いて、推測の数字や実績が入り込む余地を残す
- 基準だけ渡して、自己チェック項目の形にしない

## 最終チェック

- [ ] 冒頭に前提一文（文脈ゼロ・不足は指摘する）を付けた
- [ ] 事業の実態に、確認できる実数だけを書いた
- [ ] 背景と目的に、成功の判定まで書いた
- [ ] 仕様の形式と分量を数字で書いた
- [ ] 制作基準・好み・嫌うものを明示した
- [ ] 禁止事項に「数字・実績を作らない」を含めた
- [ ] 自己チェック項目を、チェックの形で受け手に渡した
- [ ] 固定部分（①④⑤）はテンプレートから貼り、差し替えは②③だけにした
