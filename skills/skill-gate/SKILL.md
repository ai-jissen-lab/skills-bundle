# skill-gate（外部スキル検査ゲート）

AIエージェントの「スキル」は、指示文（プロンプト）の集まりだと思われがちだが、実際には指示文に加えて、フックやスクリプトのような実行コードを含むものがある。外部スキルを取り込むということは、他人の書いた指示とコードを、自分のAIの手足として迎え入れることだ。評判が良いから、便利そうだから、という理由だけで入れるのは、素性の知らないプログラムをそのまま実行するのに近い。

このスキルは、取り込み前に必ず通す「検査ゲート」の手順。肝は3つ。

1. **検査は自分の環境の中で完結させる**。スキャンは必ず `--no-llm` で実行し、スキルの中身を外部サービスへ送らない
2. **判定ごとの扱いを先に決めておく**。結果を見てから「まあ大丈夫だろう」と判断する運用にしない
3. **入れるのはプロンプト部分のみ**。フック等の実行コードは原則として入れない

## 使う場面

- 外部スキル・プラグインを取り込むかどうか検討するとき
- スキャンで HIGH や DO NOT INSTALL の判定が出たとき
- 取り込み済みスキルの棚卸しで「あれは検査を通したか」を確認するとき

## 検査の手順

取り込み候補が出てきたら、この順で処理する。途中で落ちたら、そこで終了。

### 1. 入手先と中身を確認する

- 配布元の素性（公式か、個人か、再配布か）
- 中身の構成（指示文のみか、実行コードを含むか）

### 2. スキャンする

検査ツール SkillSpector（v2.12.0）で、取り込み候補のフォルダ全体をスキャンする。

```bash
skillspector scan <スキルフォルダのパス> --no-llm
```

- `--no-llm` は必須。外したら、その時点でこのゲートの手順から外れる。LLM解析モードではスキルの中身が外部サービスへ送られる。取り込むかどうかも決まっていない他人のコードと指示文を、検査の名目で外へ出すのは順序が逆だ
- 対象は、配布物を展開したフォルダ全体。指示文ファイルだけを選んでスキャンしない（実行コードの混入を見逃す）
- 静的スキャンで拾いきれない部分は、スコアではなく実地確認で判断する

### 3. 判定を読む

判定ごとの扱いは固定する。

| 判定 | 扱い |
|---|---|
| DO NOT INSTALL | 取り込まない。理由を問わず、そこで終了 |
| HIGH | 指摘箇所を実地で確認し、誤検知だと確認できた場合だけ先へ進める |
| それ未満 | 先へ進める。ただし「問題なし」と即断せず、指摘があれば目を通す |

扱いを先に決めておくことが大事だ。結果を見てから判断する運用だと、便利さの誘惑に判定が負ける。先に決めた扱いに従うだけ、にしておくとゲートは形骸化しない。

### 4. 移植範囲を決める

- 原則、プロンプト（指示文）部分のみを移植する
- フック、スクリプト等の実行コードは原則として入れない。指示文だけで再現できるなら、指示文だけの形に直して取り込む
- 実行コードが本体のスキルは、その時点で見送りを基本とする

理由は単純で、指示文は読めば中身が分かるが、実行コードは動かしてみるまで何をするか分からない部分が残るからだ。読めるものだけを入れる。

### 5. 自分の環境に合わせて書き換える

- パス、名前、運用ルールとの矛盾を先に潰す
- 自分の常駐ルールと衝突する指示は、取り込まないか、削ってから入れる。ルールの側をスキルに合わせて曲げない

### 6. 取り込み後に動作確認する

- 狙った場面で狙った動きをするか
- 既存のスキルやルールと競合していないか

## HIGHが出たときの実地確認

HIGHは即却下ではない。ただし、進める条件は厳しくする。

- 指摘された箇所を、原文で読む（要約やスコア表示だけで判断しない）
- 指摘が「本当に危険な動き」か「危険に見えるだけの書き方」かを分ける
- 誤検知と判断したら、その理由を記録してから進める
- 判断がつかない場合は、進めない。便利さより、止める側を取る

「理由を記録する」が効いている。後から別のスキルで同じ指摘が出たときに、過去の判断を参照できる。記録がないと、毎回ゼロから悩むことになる。

## 移植時の除外ルール

- 実行コード（フック、常駐スクリプト類）は原則除外する
- 外部へ送信する処理が含まれていたら、その部分は削るか、スキルごと見送る
- 自分の常駐ルールと矛盾する指示は、スキル側を直すか、取り込まない
- 取り込んだスキルが何をするものか、素性を1行で言える形にしておく。言えないものは、後で棚卸しもできない

チェックは `templates/intake-checklist.template.md` を使う。

## やらないこと

- スキャンをせずに「評判が良いから」で取り込む
- LLM解析モード（`--no-llm` なし）でスキャンする
- DO NOT INSTALL の判定を、理由を付けて覆す
- HIGH の指摘を原文で読まずに進める
- 実行コードを含んだまま取り込む
- 「安全そうなもの」だからとゲート自体を飛ばす（ゲートは怪しいものを止めるためだけではなく、「確認した」という記録を残すためにある）
