# correction-ledger（訂正台帳）

AIアシスタントを使っていると、一度直したはずの間違いが、しばらく経つと戻ってくることがある。その場では訂正した。AIも「分かりました」と答えた。なのに別の日、別の場面で、同じ間違いを前提に答える。訂正した事実がメモリのどこかに埋もれたか、訂正前の古い記述が別の場所に残っていて、そちらを拾ったかだ。

このスキルは、その対策として「訂正された事項だけを集めた一覧」を台帳として維持するためのルール。肝は3つ。

1. **訂正は「旧（誤）／現行（正）／検証質問の形」で1行ずつ残す**。正しい答えだけでは、どちらが現行か判定できない
2. **追加は承認不要でその日のうちに。消す・移すときだけ承認制**
3. **メモリ整理の完了条件に、訂正論点の再確認を含める**。答えが崩れていたら、その整理は完了と言わない

台帳のひな形は `templates/correction-ledger.template.md`。メモリ全体の整理の進め方は memory-metabolism スキル側にある。このスキルは、その中の「訂正を守る」部分を単独で使えるようにしたもの。

## 使う場面

- 持ち主から事実の訂正を受けたとき（その日のうちに台帳へ足す）
- メモリの棚卸し・整理をする前後（削除候補からの除外と、再確認の実施）
- 同じ間違いが再発したとき（台帳に載っているか、載せ方が崩れていないかを確認する）

## 台帳の形

訂正された事項だけを集めた、一覧のファイル。1件につき1行で、列は固定する。

| 列 | 書くこと |
|---|---|
| 論点 | 何についての訂正か |
| 旧（誤） | 訂正前の、間違った答え |
| 現行（正） | 訂正後の、正しい答え |
| 訂正日 | 訂正された日 |
| 検証質問の形 | この論点を確かめるときの質問文の型 |

大事なのは「現行（正）」だけでなく「旧（誤）」も残すことだ。正しい答えだけ書いてあると、AIが古い記述を拾ったときに、どちらが新しいのか判定できない。旧と新を並べて「こちらが誤りで、こちらが正」と名指してあるから、矛盾した記述に出会ったときの判定材料になる。

「検証質問の形」は、この論点を確かめるときの質問文の型。後述の再確認で使う。

台帳は、最初は空に近い。過去に直した事実を思い出せるだけ書き出すところからでいい。その1行ずつが、同じ間違いを二度とやらせないための材料になる。

## 運用ルールは3つ

### 1. 追加は承認不要で、その日のうちに

訂正が起きたら、その日のうちに台帳へ1行足す。持ち主の承認は要らない。記録が遅れるほど、同じ間違いが再発する期間が長くなるからだ。足すのは速く、が原則。

### 2. 消す・移すときだけ承認制

逆に、台帳の項目を消したり、メモリ整理で移設したりするときは、持ち主の承認を取る。訂正の記録は「間違いの再発防止装置」なので、整理のついでに軽く消してよいものではない。

メモリの棚卸しでも、重要な訂正（過去に誤答→修正された事項）は削除候補から外す、と決めておく。サイズや重複の観点で候補に見えても、台帳に載っている論点は候補に入れない。

### 3. 整理の完了条件に、訂正論点の再確認を含める

メモリ整理をしたときは、「過去の訂正論点を再確認し、答えが崩れていないか見てから完了とする」を完了条件にする。

やり方は単純だ。台帳から論点の違う3問ほどを選び、「検証質問の形」でAIに質問し直す。整理の前と後で同じ質問をして、答えが訂正後の内容と一致しているかを見る。1問でも訂正前の間違いに戻っていたら、その整理は完了と言わない。短くなったこと自体を成果にしない、という決まりとセットである。

## なぜ台帳が要るのか

メモリ本体に訂正を書くだけでは足りない理由は2つある。

1つは、訂正は「置き換え」だということ。新しい記述を足しても、古い記述が別のファイルに残っていれば、AIは場面によって違う方を拾う。台帳は、どちらの記述が現行かを判定する材料になる。

もう1つは、検証の対象が要るということ。メモリを整理したあと「正しく整理できたか」を確かめるには、整理前後で変わってはいけない答えの見本が要る。訂正論点は、その見本にちょうどいい。過去に実際に間違えた点だから、崩れれば実害が出るところでもある。

## やらないこと

- 訂正を、その場の会話だけで済ませて台帳に残さない
- 「現行（正）」だけを書き、「旧（誤）」を消してしまう
- 台帳の項目を、承認なく消す・移す
- サイズや重複を理由に、台帳の論点を棚卸しの削除候補に入れる
- 整理の完了を、訂正論点の再確認なしに宣言する
